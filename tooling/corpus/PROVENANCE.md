# Corpus provenance — SUBTASK H1 (DocScanAI)

This file records, for every image the corpus lane packages, where it came from and
what transformation was applied, so the corpus stays license-clean and auditable.
It complements the machine-readable `tooling/corpus/provenance_real.jsonl`.

The corpus has two halves:

| Half | Where | Count | Network at test time |
|---|---|---|---|
| **PRIMARY — synthetic (seeded)** | generated in-process by `CorpusRealLifeTest` with OpenCV Android | ~44 | none |
| **SECONDARY — real photos** | `app/src/androidTest/assets/corpus/real/` | 12 | none |

---

## 1. PRIMARY — seeded synthetic set (deterministic, no network)

Rendered inside the instrumented test from the bundled `assets/testdocs/test_page.jpg`
(so the corpus carries **ground-truth corner coordinates** and detection is scored
numerically, not eyeballed). Seed = `0x5D0C5A1` ⇒ identical images on every run.

Canvas: `1000 × 1300` portrait (its long edge is below the pipeline's own 2000 px working
cap, so no pipeline downscale distorts the ground truth). The page is pasted into the
canvas with a homography built from the scenario's destination quad; the seed controls
lighting/degradation noise only, never the ground truth.

| Category | Count | What it exercises | Ground truth |
|---|---|---|---|
| `rotation_small` | 5 | ±12–30° in-plane rotation | yes (rotated rect) |
| `rotation_90` | 3 | 88° / 90° / 92° near-quarter-turn | yes |
| `perspective_mild` | 5 | small seeded perspective | yes |
| `perspective_moderate` | 4 | moderate seeded perspective | yes |
| `perspective_strong` | 4 | strong seeded perspective | yes |
| `perspective_offcentre` | 3 | warp + translation off centre | yes |
| `partial_out_of_frame` | 3 | page partly outside the frame | yes (may exceed frame) |
| `rectified_full` | 3 | already-rectified page filling the frame | yes (= full frame) |
| `lighting_brightness` | 1 | vertical brightness ramp | yes |
| `lighting_vignette` | 1 | radial darkening | yes |
| `lighting_shadow_band` | 1 | hard shadow band across the page | yes |
| `lighting_low_contrast` | 1 | washed-out low contrast | yes |
| `degradation_blur` | 2 | Gaussian blur | yes |
| `degradation_noise` | 2 | additive Gaussian noise | yes |
| `degradation_small_scale` | 2 | page rendered small then upscaled (lossy) | yes |
| `negative_texture` | 2 | procedural desk texture/gradient, **NO document** | none |
| `negative_clutter` | 2 | busy cluttered composite, **NO document** | none |

Transformation for every synthetic image: OpenCV `getPerspectiveTransform` + `warpPerspective`
(`INTER_LINEAR`, `BORDER_CONSTANT`), then the category's post-processing (lighting/degradation).
Author: generated by `CorpusRealLifeTest` (this repo). License: N/A (derived from the bundled,
repo-owned `test_page.jpg`).

Transformations applied by the fetcher ([`FetchCorpus.java`](FetchCorpus.java)):
- Non-bitmap or non-permissive candidates are **skipped** (never fabricated).
- Images whose long edge exceeded 3000 px were bilinear-downscaled to 3000 px; the rest
  were stored as downloaded. See the `transform` field per line in the JSONL.

### Downloads skipped for time / rate limits

The lane's optional secondary network step is **hard time-boxed to ≤ 3 minutes** with a
15 s per-request timeout and *immediate skip on HTTP 429*. The 12 photos above were
already fetched by the earlier run, so **no additional downloads were attempted** — the
lane proceeded with the packaged set (per the "never block the lane on the network" rule).
Any future additions must be recorded in the table above and in the JSONL.

`CorpusRealLifeTest` auto-discovers every image file in that folder (sorted, filtered by

## 4. BENCHMARK — real document-rectification photographs (SUBTASK H3a)

Added by SUBTASK H3a: a purpose-built **real** rectification benchmark, packaged under
`app/src/androidTest/assets/corpus/benchmark/` and reported as its own group (separate from the
synthetic set and the not-a-document negatives).

### 4.1 Source: DocUNet Benchmark

| Field | Value |
|---|---|
| Dataset | **DocUNet Benchmark** — *"DocUNet: Document Image Unwarping via A Stacked U-Net"*, Ke Ma, Zhixin Shu, Xue Bai, Jue Wang, Dimitris Samaras, CVPR 2018 |
| Project page | `https://www3.cs.stonybrook.edu/~cvl/docunet.html` |
| Rights holder | Ke Ma / Stony Brook University Computer Vision Lab |
| License | Academic benchmark. The project page states no explicit license; it is published for research/evaluation. Used **locally for testing only** and **not redistributed**. |
| Archives | `http://vision.cs.stonybrook.edu/~kema/docwarp/original.zip` (344,449,749 B, real photos) and `http://vision.cs.stonybrook.edu/~kema/docwarp/scan.zip` (436,458,210 B, flatbed scans) |
| Retrieval method | **HTTP Range streaming, NOT a full-archive download.** Two small Range requests read each ZIP's central directory, then each kept entry's local header + deflate payload is fetched individually. If the server ever answered `200` (Range ignored) instead of `206`, that source would be abandoned rather than pulled whole. |

### 4.2 What was kept

- **20 pages** out of the 65 pages in `scan.zip`, picked **evenly across the page axis**
  (pages 1, 4, 8, 11, 14, 18, 21, 25, 28, 31, 35, 38, 41, 45, 48, 52, 55, 58, 62, 65) so the subset
  spans the whole range of capture conditions; the two shots per page are alternated.
- `inputs/docunet_<NN>.jpg` — the **real photograph** (`original/<n>_<shot>.jpg`).
- `gt_scan/docunet_<NN>.jpg` — the matching **flatbed scan** (`scan/<n>.png`) of the SAME page, the
  PSNR/SSIM ground truth.
- **Corner ground truth: NONE.** DocUNet publishes scan GT, not corner annotations, so
  `gt_corners/` is empty and corner-error / placement verdicts read `n/a` for this group. The
  drop-folder documents how to add corner GT for your own images.
- Transformations applied: long edges > 3000 px were **bilinear-downscaled to 3000 px**; smaller
  images were stored as-is; everything was re-encoded as JPEG q≈0.90. Per-file detail (source and
  destination sizes, both archives' entry names, byte counts) is in
  [`provenance_benchmark.jsonl`](provenance_benchmark.jsonl).

### 4.4 Sources evaluated and SKIPPED (with reasons)

| Candidate | Outcome | Why |
|---|---|---|
| DocUNet official `original.zip` / `scan.zip` | **USED** (Range-streamed subset) | Server supports `Accept-Ranges: bytes` (206), so only the kept entries were transferred |
| DocUNet mirror `AndrewDufren/DocUnet` (HuggingFace) | skipped | Single `DocUnet.zip` of **1.66 GB** (plus 10 GB+ sibling archives) — a monolithic archive, not per-file |
| UVDoc released eval data (`UVDoc_final.zip`, `UVDoc_benchmark.zip`, `UVDoc_raw.zip`) | skipped | Single large archives on `igl.ethz.ch`; the geometry ground truth is `.mat`/`.exr` (no reader without new dependencies) |
| `malper/UVDoc_cn` (HuggingFace) | skipped | Parquet-only (28 shards, ~0.5 GB each); would need a Parquet reader = new dependency |
| `34data/WarpDoc_merged`, `34data/SmartDoc-QA` (HuggingFace) | skipped | Parquet-only, and the modality tag is `text` |
| `StonyBrook-CVLab/doc3D-dataset` (HuggingFace) | skipped | `gated: auto` → requires accepting terms / auth |
| `TilanB/smartdoc-samples` (HuggingFace) | skipped | `gated: auto` → requires auth |
| `Noaman/midv500` (HuggingFace) | skipped | Parquet-only (no per-file images); MIDV corner annotations would need a Parquet reader |
| DIR300 | skipped | No per-file host or HuggingFace mirror found; upstream distribution is a large archive |
| SmartDoc / ICDAR 2015 doc-capture | skipped | Not directly downloadable per file from a stable host within the time budget |
| Google Drive / Baidu hosts | skipped by policy | Not directly downloadable per file |
