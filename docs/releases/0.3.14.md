# DocScan AI 0.3.14

On-device Android document scanner. Kotlin + Jetpack Compose, ONNX models, no cloud, no account,
no OCR.

## Downloads

| File | What it is |
|---|---|
| `DocScanAI-0.3.14.apk` | **Signed release build — use this one** |
| `DocScanAI-0.3.14-debug.apk` | Debug build (different signing key; for bug reports only) |

- `arm64-v8a` + `x86_64`, Android 8.0+ (API 26), no Google Play services required.
- SHA-256 and byte sizes are in the release notes below and in `SHA256.txt`.

## Install

```bat
adb install -r DocScanAI-0.3.14.apk
```

Installing over Wi-Fi or copying the APK to the phone also works. **If a debug build is already
installed, uninstall it first** (`adb uninstall com.docscanai`) — the two use different signing
keys.

> **About Android's "unverified developer" prompt.** Google's developer-verification enforcement
> (Oct 2026) currently applies to apps installed from seven *app stores* in Brazil, Indonesia,
> Singapore and Thailand. A direct APK download is not covered yet. Where it does apply, Android
> asks once per device for a one-time "advanced flow" (enable Developer Options → restart → wait
> 24 h). **`adb install` is always exempt** — use it to avoid the wait entirely.

After install the app offers a one-time in-app model download. Skipping it still works (built-in
perspective correction + enhancement); no feature is locked.

## Changes since 0.3.13

### Detector

- **One weak corner channel no longer discards a page.** The corner-heatmap gate used a flat
  0.30 per-channel floor. When three channels are confidently above `0.35`, the fourth may now
  pass at `0.22`. A photo where the model is genuinely blind cannot reach that condition, so this
  is not a global threshold drop.
  Measured on the 116-photo real-path lane:

  | metric | 0.3.13 | 0.3.14 |
  |---|---|---|
  | detected | 96 | **97** |
  | corner-model quads | 31 | **33** |
  | no-detection | 20 | **19** |
  | wrong-page | 17 | 17 |
  | merged | 27 | 27 |

  Two photos changed, both improved; nothing got worse. The applied floor is recorded per photo in
  the diagnostics trace (`corner_post.peak_floor_applied`).

### Diagnostics / evidence harness

- **The gate's INK map is now provably not the detector.** New tooling replays stills through the
  real pipeline and dumps, per photo: the exact corner-model tensor, the four AI corner heat maps,
  the final quad, and the gate's rectified page + INK map + glyph components — alongside the same
  photo re-rectified with a ground-truth quad. Measured over 116 photos: the correct quad does
  **not** score better on the ink evidence than a merged one (mean text-score change −0.183,
  all separation AUCs ≈ 0.5), so ink thresholds cannot fix the merged class. See
  `docs/evidence/README.md`.
- `DOCSCAN_TRACE_JSON_ONLY=1` traces all 116 photos in ~12 s (scalars only, no PNGs).
- Fixed: the trace lane aborted after every device pull, so `raw/` was always left behind.
- Fixed: lane heartbeat messages containing `>` created junk files (e.g. `uninstall`) at the repo
  root.
- Fixed: the previous photo's M-LSD log leaked into the next photo's trace scene.

### This is not a regression-free claim for everything

`DetectionRegressionTest` (2 of 5) and `DewarpFidelityTest` (2 of 5) fail on this tree **and on
0.3.13** with byte-identical numbers — they are pre-existing. `DewarpFidelityTest` additionally
needs the separately-provisioned `m2_dewarp_grid` model.
