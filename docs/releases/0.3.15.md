# DocScan AI 0.3.15

On-device Android document scanner. Kotlin + Jetpack Compose, ONNX models, no cloud, no account,
no OCR.

## Downloads

| File | What it is |
|---|---|
| `DocScanAI-0.3.15.apk` | **Signed release build — use this one** |
| `DocScanAI-0.3.15-debug.apk` | Debug build (different signing key; for bug reports only) |

`arm64-v8a` + `x86_64`, Android 8.0+ (API 26), no Google Play services required.

## Install

```bat
adb install -r DocScanAI-0.3.15.apk
```

If a **debug** build is already installed, uninstall it first (`adb uninstall com.docscanai`) —
the two use different signing keys.

> **Sideloading note.** Google's developer-verification enforcement currently applies to apps
> installed from seven *app stores* in Brazil, Indonesia, Singapore and Thailand; a direct APK
> download is not covered yet. Where it does apply, Android asks once per device for a one-time
> "advanced flow" (enable Developer Options → restart → wait 24 h). **`adb install` is always
> exempt.**

The app offers a one-time in-app model download (~35 MB). Skipping it still scans; no feature is
locked.

## Changes since 0.3.14

### Model setup screen — the duplicate / dead entries are gone

The onboarding screen used to list **six** entries totalling ~110 MB, four of which were
misleading:

| old row | what it really was | now |
|---|---|---|
| Page detector — DexiNed, 45 MB | legacy boundary graph, not consulted by detection since H4 | removed from the UI (still in the registry for tooling/rollback) |
| Page flattening — UVDoc, 30 MB | image-to-image export, only a fallback behind the grid path | removed from the UI |
| Page flattening — UVDoc 45x31 grid, 30 MB | the real dewarp path | **kept**, now labelled "Page flattening" |
| DRCNet / PaperEdge, 150 MB | URL was a `TODO` placeholder — could never download | hidden until pinned |
| DewarpNet WC, 8 MB | placeholder, same | hidden until pinned |
| DocShadow, 60 MB | placeholder, same | hidden until pinned |

The screen now shows exactly what the pipeline reads:

- **Page detector** — `DocAligner LCNet100` corner heatmap, ~5 MB
- **Page flattening** — `UVDoc` 45×31 grid, ~30 MB
- button: **Download AI models (~35 MB)**

Mechanism: `ModelSpec.userFacing = false` on the non-offered artifacts, `fastTierIds` reduced to
the two the pipeline actually requires, and a new `ModelRegistry.downloadableSpecs` drives the
list. They stay registered so presence checks, `_provision_models.cmd` and the instrumented tests
keep working unchanged.

Verified on an API 35 emulator: two rows, correct subtitles, one 35 MB download button, no
placeholder rows.

### Run records published (read results without running the app)

New `docs/runs/` holds the machine output of the measurement lanes as text:

- `detector-116.md` — the detector verdict over all 116 owner photos, 0.3.13 vs 0.3.15 side by
  side, per-photo quad/IoU/corner-error table, and the corner-model blind-spot breakdown.
- `ship-0.3.14.md` — build identity, certificate continuity, SHA-256 and the install/launch smoke
  for the previous release.

Regenerate with `python tooling\h42_publish_runs.py`.

## Unchanged detector (carried from 0.3.14)

One weak corner channel no longer discards a page: when three channels are confidently above
`0.35`, the fourth may pass at `0.22`. Measured on the 116-photo lane: detected 96 → **97**,
corner-model quads 31 → **33**, no-detection 20 → **19**, wrong-page and merged unchanged.
