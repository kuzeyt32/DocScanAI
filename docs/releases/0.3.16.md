# DocScan AI 0.3.16

The first build where the detector becomes **primarily AI-driven** instead of falling back to the
classical path.

## Downloads

| File | What it is |
|---|---|
| `DocScanAI-0.3.16.apk` | **Signed release build — use this one** |
| `DocScanAI-0.3.16-debug.apk` | Debug build (different signing key; for bug reports only) |

`arm64-v8a` + `x86_64`, Android 8.0+ (API 26), no Google Play Services required.

```bat
adb install -r DocScanAI-0.3.16.apk
```

Uninstall a debug build first if one is installed (`adb uninstall com.docscanai`). `adb install`
is exempt from Android's unverified-developer flow; a direct download may need the one-time
"advanced flow" (Developer Options → restart → 24 h) where Google's enforcement applies.

## What was actually wrong

The owner reported for months that "the model is not good enough." Half right — the model was fine,
**the input was destroying it.**

### 1. The model was fed an aspect-squashed image (letterbox fix)

`Bitmap.createScaledBitmap(bitmap, 256, 256, true)` squashes a 4:3 phone still into a square. The
page arrived stretched 33 % vertically, and a corner regressor trained on undistorted pages returned
nothing. Now the input is letterboxed — aspect preserved, flat grey pad, cubic resampling — and a
heat peak landing on the pad is rejected rather than mapped to a fake corner.

| input construction | photos with a 4-corner lock | model quads matching the page |
|---|---|---|
| squash + bilinear (0.3.15) | 30 | 23 |
| squash + cubic | 33 | 25 |
| **letterbox + cubic (0.3.16)** | **61** | **42** |

### 2. Small pages got lost among other sheets (multi-crop rescue)

When a page fills little of the frame (a green workbook among white papers), even the fixed input
returns peaks of ~0.001. If the full-frame pass fails **on a still/import**, the model now retries
on 4 overlapping quadrants plus a centre crop and takes the first plausible result.

| strategy | model quads matching the page |
|---|---|
| full frame only | 42 |
| **best of 6 crops** | **52** |

All 10 gained photos had *no* full-frame lock, so the retry is skipped for everything that already
works — the preview path is untouched (the retry is still-only: ~220 ms once per capture, too slow
for 30 fps).

## Colour was not the cause

Measured with the paper colour taken *inside* the page (not the frame):

| paper class | photos | miss rate |
|---|---|---|
| white / neutral | 34 | 24 % |
| tinted | 67 | 7 % |
| green / coloured | 13 | 15 % |

White pages are missed **more** than coloured ones. The green-photo failures were a *size* problem,
which is what the multi-crop fix addresses.

## Fixed along the way

- **Silent channel-mismatch bug (mine, caught before release):** `Utils.bitmapToMat` returns RGBA;
  copying into a 3-channel canvas fails *without throwing*, so the model was fed pure padding and
  CORNER_MODEL dropped to zero. Preprocessing now normalises to BGR and asserts the composite is
  not empty.
- **`corner_input.png` in the trace dump** now shows the real letterboxed model input instead of the
  old squash, so the evidence matches reality.
- **Model setup screen** offers only the two artifacts the pipeline reads (~35 MB instead of ~110 MB).
  The legacy DexiNed graph and three never-pinnable placeholders are hidden (still registered, for
  tooling and rollback).
