## Context

Repo: DocScanAI (Kotlin/Android, OpenCV, ONNX Runtime, models loaded at runtime).
Detection today: DocAligner LCNet100 corner model + classical OpenCV fallbacks + a stack of
hand-written gates. It is a SINGLE-DOCUMENT corner detector.

What we have already measured - do NOT re-derive these:
- It cannot handle two-page spreads reliably. Its own paper (arXiv 2306.05749, Appendix F)
  states: orientation must be upright, "Incomplete" (partly out-of-frame) documents are
  unsupported, large rotations are excluded. These map exactly onto observed failures.
- 6 of 42 holdout photos are "one-leaf locks" (quad covers one leaf of a two-page target);
  9 of 94 on the owner set. So it is a general weakness, ~10-14% of captures.
- The best possible quad for those photos scores median IoU 0.98, and 40 of 42 are reachable
  at IoU >= 0.85 while the detector reaches 23. The loss is quad CHOICE, not quad SHAPE.
  Do NOT build polygonal-crop machinery to fix coverage; it is not the issue.
- Rejected with measurements, do not retry:
  * luma-based edge extension: fired 29, helped 9, hurt 19 (white page on white table)
  * M-LSD merge-repair splitting: damaged 36 of 38 photos it touched; currently disabled
  * "is there paper outside the quad" panel test: does not separate panel from page
- The SAM-based measuring mask over-covers (it includes the page fanned out BEHIND the front
  one) on ~5 of 16 short cases. It is a pre-annotation tool, NOT ground truth.

## Decision already made

Replace the hypothesis: instead of "a page is 4 corners", predict PAGE INSTANCES (masks),
then fit a quad or mesh.

  PREVIEW  tiny net (256 grayscale) -> coarse instances + Kalman filter + IMU gate
  CAPTURE  full-res instance segmenter (the real model) -> decision layer:
             drop instances cut by the frame (a partly-seen leaf is not the target)
             rank by area / centre / ink
             two adjacent similar instances -> SPREAD (union of both)
             one dominant -> SINGLE PAGE
           -> contour -> quad fit -> subpixel edge refinement (already exists, keep it)
  WARP     homography for flat pages, mesh for curved

Rationale from industry primary sources: Scanner Pro runs a small keypoint net on every frame
and a heavier segmentation model at capture; Genius Scan used MobileNetV2 at 96x96 then
refined the quad classically (51% -> 75% -> 85%); Adobe uses a 64x64 cascade at 557 fps and
labels "two pages" explicitly. Genius Scan at 85% still lists "better manage the detection of
book pages" as FUTURE work - this is genuinely the hard case.

Model to train: small 3-class instance segmenter (page / gutter / hand), MobileNetV3 backbone,
~5M params, exported to ONNX. Not a foundation model.

## Phases

P0 instrument (before any model work)
  - Rotation harness: replay the existing holdout42 photos at 0/90/180/270 degrees through
    the UNCHANGED detector. Quantify the rotation dependence the user reported.
  - Build INSTANCE-level ground truth (each leaf its own instance), replacing the over-covering
    SAM mask as the referee. SAM may propose; a human decides.
  - Evaluate bookspread_real with the same harness - it was never scored before.
  - Gate: rotation effect quantified; phantom failures removed from the baseline; a clean
    before-number on all real sets.

P1 synthetic factory - only for classes real photos cannot cover
  - Inputs: clean page images composited into single page / two-page spread with gutter and
    cylinder curvature / panels lying on a page / frame-cut pages / random 90-degree rotations.
  - Use REAL background plates and REAL shading maps photographed by the user, plus the
    measured noise, blur and JPEG quality of the user's camera.
  - Synthetic supplies LABELS (topology, rotation, truncation), never APPEARANCE.
  - Deliberately soften composite edges (real page boundaries are 2-4 px soft).
  - Track a real-vs-synthetic classifier accuracy and a synthetic-only -> real transfer test.
    If transfer collapses, drop synthetic and say so.
  - Gate: visual audit - synthetic must be hard to mistake for the user's real photos.

P2 train the segmenter
  - REAL-ONLY BASELINE FIRST (~100 train photos). Then add synthetic only for starved classes
    (rotated spreads, frame-cut pages, two-leaf topology - where real examples number < 20).
  - Heavy augmentation including random 90-degree rotation (Adobe does this because phone
    orientation metadata is unreliable).
  - Gate: on held-out real photos, instance IoU >= 0.90 median; 1-vs-2 leaf decision >= 95%.

P3 pipeline v2
  - Decision layer as pure logic, unit-testable offline. Kalman + IMU. Two-stage preview.
    Mesh warp for curved pages.
  - Optional only if needed: pseudo-sequences (random small homography + brightness jitter)
    with N frames as input channels. Do NOT collect real video for this.
  - Gate: >= 15 percentage points absolute gain; zero regressions on any existing set.

P4 honest evaluation
  - Freeze code, run ONCE on the sealed set, publish that number even if it is lower.
